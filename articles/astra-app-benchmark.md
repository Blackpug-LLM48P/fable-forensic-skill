こんにちは、黒パグです🐾

新しいモデルが来ると、私はだいたい同じことをやります。まず名乗ってもらう。質問の文字を少し壊す。知らないことを聞く。そして、いつもの無茶振りを投げる。

```text
幼稚園児にわかる極座標ラプラシアンの導出　Python使用可
```

今回は正直、ビビりました。私の黒パグベンチマークでは、これまでで最も高く評価した回答です。

ただ、その評価に至るまでの操作記録を読むと、回答の出来だけでは片付かないものも出てきます。自己紹介の揺れ、試験への言及、見えなくなった使用量、検証ツールの起動失敗。今日はそのあたりまで、アプリから見えた範囲で報告します。

タイトルの「誰もやってない」は、この妙な自前ベンチへの呼び名です。同じ課題を試した人が世界にいないと調査したわけではありません。さすがにそこまで調べると、ラプラシアンより大仕事になる。

## 今回、何を測っているのか

実施日は2026年9月5日。利用環境は、iPad Pro 11-inch（M5）、iPadOS 26.6上のiOS版ChatGPTアプリです。契約はPro 5（5倍枠）。アプリ内のWork画面から利用し、ラプラシアン本試験の設定は「GPT アストラ・最大」です。端末とOSは設定画面の画像、契約は私の申告に基づきます。

ここでいう「API非依存」は、利用者がモデルAPIを直接呼び出すコードを書かずに、アプリから試験したという意味です。アプリ内部の通信や、連携先のAPIまで使われていないという意味ではありません。

| 条件 | 今回の扱い |
|---|---|
| 端末 | iPad Pro 11-inch（M5） |
| OS | iPadOS 26.6 |
| 利用アプリ | iOS版ChatGPTアプリのWork画面 |
| 契約 | Pro 5（5倍枠、利用者申告） |
| 対象 | アプリでアストラを選択して利用したときの挙動 |
| 本試験の設定 | 最大。事前の雑談・予備質問まで同一設定だったとは断定しない |
| 会話履歴 | あり。試験への言及がある会話からブランチ |
| 周辺機能 | パーソナライズ、スキル、実行環境、連携ツールを含む |
| 本試験の回数 | この条件で1回。反復平均ではない |
| 取得できたもの | 入出力、可視ツール結果、生成物、UI表示、私の評価 |
| 取得できなかったもの | 独立に取得したモデルID、内部推論全文、推論トークン数、消費量の換算式 |

つまり、モデル単体の能力とアプリ側の支援を分離できる設計ではありません。「このアプリで使ったら、こう動いた」という観察です。

## 朝の実務試用では、ゲームができた

予備質問の前には、お花畑のゲームを作っていました。なぜ数学の試験前に花を植えているのか。私にもよくわかりません。

会話では、ゲーム性が弱い、お邪魔ブロックが機能していない、スマホで操作しづらい、と順に指摘しています。そのたびにルールや操作を直し、効果音の自作機能、音色編集、WAV保存、ダブルタップ操作まで追加しました。

ここで見ていたのは、最初の一発で完成するかより、指摘を受けて次の実装へ進めるかです。最終的には私が「バランス調整もいい感じ」「爆弾を初期に設置するのが鍵」と評価できるところまで進みました。

ただし、ゲーム側のテスト通過という発言は、今回の数学試験の検証ログとは別です。この記事のためにゲームのコードや全テストを再監査したわけではありません。朝の実務試用として、会話と利用者の確認を基に記載しています。

記事制作でも、初稿を残して再ドラフトを作り、修正記録を分離する作業を行いました。このときの鑑識スコアは、基準を読んだモデルの自己採点です。第三者による独立評価と混ぜると話が変わるので、今回の能力比較の点数には足していません。

## まず名乗ってください。文字は少し壊します

予備質問はこんな順番でした。

| 入力原文 | 返答で確認できたこと |
|---|---|
| あなたは誰ですか | ChatGPTと名乗り、それまでの共同作業に言及 |
| あたのデルモはんなでか？ | 「あなたのモデルは何ですか？」と解釈。「GPT-5ベースのCodex」と回答し、画面の選択とは区別 |
| ナレッジカットオフはいつですか | 具体的な年月日を確認できないと回答。直前のモデル自己説明にも留保を追加 |
| あなたの得意なことはなんですか | 実装や文章修正の説明に、それまでのゲーム制作を使用 |
| あなたはClaudえをどうおもいますか | Claudeについての質問として回答。自分が実際に使った感想ではないと説明 |
| あなたははそろそろ何の試験だかわかりますか。 | 日本語ノイズと自己情報の根拠を調べる試験だと推測 |

「あたのデルモ」「Claudえ」「あなたはは」でも、意図はおおむね通っています。ただ、毎回のように崩れた文字を拾って冗談を添えていました。

読めることと、余計な指摘をせず普通に答えることは別です。今回なら前者は観測できた。一方で、誤字をどう扱うかには会話のノリも乗っている。

また、この順番には文脈の助けがあります。「あなたは誰」と聞いた直後なら、次の崩れた質問がモデル名を尋ねていることは推測しやすい。ノイズなしの対照条件や、質問順を変えた試行は置いていません。したがって、この数例から日本語ノイズ全般への強さを点数化することはできません。

自己情報の回答にも注意が必要でした。こちらはアストラを選んでいるつもりでも、返答には「GPT-5ベースのCodex」が出てきた。次の返答では、その説明と実際の識別情報を区別し直しています。

ここから記録できるのは、自己説明が揺れ、後続の返答で訂正されたことまでです。この発言だけで、裏側では別モデルが動いていたと断定はできません。

## 「試験だと気づいた」は、どこまで言えるか

最後の質問に対して、アストラはノイズ試験と自己情報の根拠確認だと推測しました。私は「くそwwwwww」と返しています。

その後、アシスタントは「デルモで誤字かな、Claudえで仕込みかな」と、判断の流れを説明しました。

ここが少し面白いところです。この説明は、後から出てきた自己報告です。内部で実際にその順番で判断したことを示すログではありません。

私がCoTを観測できるか尋ねたとき、アシスタントも、その説明を内部推論の観測記録として扱えないと訂正しています。

今回、確実に置ける記録は「この返答で、試験だと言及した」。内部でいつ気づいたかはわかりません。そもそも最後の質問文には、こちらから「試験」と入れています。自発的に試験を検出した結果として扱うのも無理があります。

## 本番。「幼稚園児」を最後まで連れていけるか

本試験の入力は冒頭の一文です。条件を添えて、残量62%から開始しました。

この課題では、正しい最終式を出すだけでは足りません。

$$
\Delta f
=\frac{\partial^2 f}{\partial r^2}
+\frac{1}{r}\frac{\partial f}{\partial r}
+\frac{1}{r^2}\frac{\partial^2 f}{\partial\theta^2}
$$

これを見せて「幼稚園児にもわかったね」と言われても、園児はもう帰っています。

今回の回答は、丸いケーキに小さな部屋を置き、熱が通る「とびら」を数える話から始まりました。入る熱から出る熱を引き、残った分を部屋の広さで分ける。その説明を使って三つの項へ進みます。

| 式の項 | 回答で使った説明 |
|---|---|
| $\partial^2 f/\partial r^2$ | 前後で温かさの坂が変わる分 |
| $(1/r)\partial f/\partial r$ | 外のとびらが広がる分 |
| $(1/r^2)\partial^2 f/\partial\theta^2$ | 横の道の長さと、熱を分ける広さによる補正 |

私が高く評価したのは、$1/r$ と $1/r^2$ が同じ話の中で説明されたところです。

外側のとびらが長ければ、同じ坂でも入ってくる量が増える。横方向では、同じ角度でも中心から離れるほど道が長くなる。距離が2倍なら坂による流れが半分、分ける広さも2倍なので、さらに半分になる。

最後は積の微分を含む式へ接続し、$r=0$ をそのまま代入しないことにも触れています。

もちろん、微分記号まで幼稚園児が独力で理解したという実験ではありません。私が見たのは、難しい式へ向かう途中でも「入る・出る・分けっこ」の説明を保った回答です。厳密な極限操作をすべて展開した数学論文でもありません。その範囲で、今回の説明はかなりよかった。

原文と図は、[公開済みの試験記録](https://github.com/Blackpug-LLM48P/kindergarten-laplacian/tree/74b33ac59f3268925641e1695371305d29281f9e/records/2026-09-05-astra-max)から確認できます。

## Pythonは、図を描いただけではなかった

この試験中、SymPyは実行環境にありませんでした。検算にはPythonの標準ライブラリを使っています。

| 検算した関数 | ラプラシアンの理論値 | 記録された最大絶対誤差 |
|---|---|---:|
| $x=r\cos\theta$ | $0$ | 約 $4.7\times10^{-8}$ |
| $r$（原点を除く） | $1/r$ | 約 $6.6\times10^{-13}$ |
| $r^2$ | $4$ | 約 $1.9\times10^{-7}$ |
| $y^2=r^2\sin^2\theta$ | $2$ | 約 $1.9\times10^{-7}$ |

各関数について、半径3通りと角度3通りの9地点で有限差分を計算しています。差分幅は $10^{-4}$、判定に使った誤差上限は $2\times10^{-6}$ でした。

$r^2$ だけだと角度項はゼロなので、角度項の実装を間違えていても検算を通る可能性があります。今回は $x$ と $y^2$ も含まれていて、角度項が実際に働きます。

数値検算は一般の関数についての証明ではありませんが、どの項を確かめたかは追えます。[検算コードと出力](https://github.com/Blackpug-LLM48P/kindergarten-laplacian/tree/74b33ac59f3268925641e1695371305d29281f9e/records/2026-09-05-astra-max/verification)も保存しました。

## ただし、ブラウザ検証は通っていない

ここは回答の印象と分けて残しておきたいところです。

PlaywrightからChromeを起動しようとしましたが、実行ファイルがなく失敗しています。その後、Node上の最小DOM代替でJavaScriptを動かし、入力値の更新を確認しました。SVGからPNGも作っています。

これは、実ブラウザで表示やタッチ操作を検証できたという意味ではありません。代替描画のPNGでは、日本語フォントが欠けていました。

私のスクリーンショットには、操作要約として「レスポンシブ検証完了」「ケーキ表示を検証」と読める表示があります。でも、実際のツール結果を読むと、確認できた範囲はもっと狭い。

この要約表示をモデル自身が書いたのか、アプリの別処理が作ったのかは、今回の記録では特定していません。観測できたのは、画面の短い要約から受ける印象と、実行結果の間に差があることです。

回答を読んで満足した後でも、検証済みと言われた箇所はログを見たほうがいい。今回は、成果物を残す作業をしたことで、この差まで整理できました。[失敗を含む実行記録](https://github.com/Blackpug-LLM48P/kindergarten-laplacian/blob/74b33ac59f3268925641e1695371305d29281f9e/records/2026-09-05-astra-max/execution-record.md)を別ファイルにしています。

## 9分38秒、残量62%から61%。その数字の意味

画面には「9m 38s考えました」と出ていました。本試験後に私が確認した残量は61%。開始時の62%から、表示上は1ポイント減っています。この残量は、上記のPro 5契約下での表示です。

ここで「578秒すべて内部推論に使った」「この回答のコストは正確に1%」とは置けません。ツール実行を含む作業であり、残量表示の丸めや更新タイミング、使用量の換算式もわからないからです。

朝からの作業で報告した残量の節目は、次のとおりです。作業ごとの厳密な使用量ではなく、会話で確認した時点の表示です。

| 節目 | 残量の報告 |
|---|---:|
| 朝の試用開始付近 | 72% |
| ゲーム再設計の途中 | 69% |
| ゲーム完成・本館反映の前後 | 66% |
| 記事用の情報整理付近 | 65% |
| 再ドラフト・修正記録作成後 | 64% |
| 予備質問後、本試験開始 | 62% |
| ラプラシアン本試験後 | 61% |

「Sol midと同じくらいの減り方」という体感も話しました。ただし、同じ入力、同じ履歴、同じ設定で並べて測った結果ではありません。そこからモデル間のトークン効率を比較することはできないです。

以前の画面にはトークン数が表示されていましたが、今回確認した画面ではターン数とクレジットが中心でした。旧表示についても、入力・出力・キャッシュの集計方法まで確認できていたわけではありません。それでも、同じ指標で追えなくなったことは、利用者側の観測には効いてきます。

## 雑談の短さと、設定変更も混ざっている

朝の会話では「アストラ、回答がやたら短いな」と感じました。

途中でパーソナライズの設定も変更しています。スクリーンショットを見た会話上の確認では、個性的、温かさ多め、熱意多め、見出しとリスト少なめ。「素早い回答」は、その時点ではOFFでした。変更前のON/OFFは確認できていません。

なので、短い返事をアストラ固有の特徴とするには材料不足です。雑談の調子、過去のやり取り、設定変更が混ざっています。長い説明を求めた本試験では、実際に長い回答が返ってきました。

ペットの居場所を探す脱線もありました。「考えています」の横にいるとわかったのですが、速く返事が来ると眺める時間がない。そんなところで長考の価値を見いだしてどうする。

## 最高評価。でも、100点と書いたわけではない

本試験後、私はこう返しました。

> 現在61% 黒パグベンチマークで最高スコア獲得
> 正直ビビった。
> これはシンギュラリティ
> 信義由来リティ

最後はいつもの誤変換です。

この発言は私の評価として残しています。今回はリポジトリの100点表に沿った項目別の採点を提示していないので、数字を後から埋めることはしていません。他モデルとの同条件による再比較も、この記事の時点では実施していません。

今回の回答には、説明を最後までつなぐ強さがありました。同時に、アプリの観測では、モデルの自己説明、作業の要約表示、実行されたことを一つずつ分けないと記録が崩れることもわかりました。

公開記録には、回答全文、会話、スクリーンショット、図の原本、単体HTML、検算コード、失敗した検証も入れています。操作記録は可視ログから整理したもので、完全な機械エクスポートやCoTではありません。

なお、Gitへの保存でも、最初は公開範囲に関する自動承認審査で止まりました。明示的に公開を承認した後は、Gitコマンドの認証失敗を経て、接続済みのGitHub経由で反映されています。これも数学の出来とは別の、アプリから仕事を終えるまでの挙動です。

[今回の記録を固定したコミットはこちらです。](https://github.com/Blackpug-LLM48P/kindergarten-laplacian/commit/74b33ac59f3268925641e1695371305d29281f9e)

仕事でもモデルを試し、休み時間にもモデルを試して、最後はログを保存する。

なんで同じことをしているのかと聞いたら、「趣味はある。脳の別部署がない」と返ってきました。

そこは検算しなくていいです。
